# bbox 条款级轮

单独一轮，只改一件事：**让每条引用指向页内某一行，而不是整页**。评测口径随之从「有没有页码」升级到「框能不能定位」。

## 问题

索引切段时把一页里若干个文字块拼成一段（380 字），段级 bbox 取这些块的**并集**。一段差不多铺满半页到整页，于是：

- 142/281 条引用是「整页框」（高度 > 60% 页高），指不到具体位置；
- 抽取段要求 `page + bbox + text` 才算有出处，框不准时整行进 `rejects`——崇左 133 行里有 19 行因此拿不到条款，校验段根本看不到它们（这正是上一轮「行级扫描」要补的窟窿）。

块本身其实很窄：三份文档文字块高度中位数 12 / 10 / 14pt，超过 60% 页高的块各只有 0 / 1 / 0 个。**框大不是块大，是并集大。**

## 改法

1. `chunk_pages` 保留段内每个块的 `text` + `bbox`，同时在元数据里存 `page_height`；段级并集只作兜底。
2. 新增 `pick_block(query, blocks, page_height)`：在段内挑和检索词**字面重合最多**的那一块；同分挑更矮的（更可能是一行条款）。块高超过 60% 页高时标 `kind="page"`，如实记账。
3. `SectionIndex.search()` 改为返回块级框：`bbox` = 最匹配的块，`bbox_union` = 段并集（调试用），`bbox_kind` ∈ `block|page|chunk`。
4. 索引格式变了，加版本闸：`INDEX_VERSION = 2` 写进 `manifest.json`，`index_cache_exists()` 版本不符即判失效——否则会拿旧并集框冒充新块级框。
5. 新指标脚本 `eval/bbox_report.py`：把每条 ref 归为 `none / page / block` 三档，算「条款级占比」，支持前后两目录对比。

## 实测（三份样本，同一批模型调用）

| 文档 | 条款级占比 | 整页框 | 无框 |
|---|---|---|---|
| beijing_road | 39% → **100%** | 60 → 0 | 0 → 0 |
| chongzuo_green | 54% → **100%** | 40 → 0 | 0 → 0 |
| wenling_video | 56% → **100%** | 42 → 0 | 0 → 0 |
| 合计 | 49% → **100%** | 142 → 0 | 0 → 0 |

框高中位数：beijing 12pt、chongzuo 10pt、wenling 14pt——基本就是一行字的高度。

连带效果：崇左 `extract.rejects` 从 19 条降到 1 条，`clauses` 从 39 涨到 64（更多行拿到条款，才可能被校验段检查）。

## 命令

```bash
# 重建索引（格式变了必须重建；版本闸也会自动判定失效）
python eval/run_engine.py --engine v2 --rebuild-index

# 前后对比
python eval/bbox_report.py /tmp/before_bbox eval/engine/v2

# 单元测试
python -m pytest tests/test_bbox.py -q     # 7 passed
```

## 门禁结果（v2 × 3 次，3 份）

| 项 | 数值 |
|---|---|
| 正例 | 16/18（稳定 15/17） |
| 负例 | 3/3，违规 0 |
| flaky | 1（`wl-perf-bond`） |
| ★ 覆盖页 | 2/16（与上一版相同） |
| 耗时 | 162s |

**这一轮不是提分轮，是提精度轮**：分数只要不掉，框必须变准。

顺手修了门禁的一个比较 bug：原来拿「稳定题得分总数」跟上次比，而这轮温岭有 4 题变 flaky、稳定分母从 16 缩到 14，分数从 15 掉到 12，被判成「退化」。现在只在**两次都稳定**的题上逐题比（`common_stable()`），掉的题会点名报出来。

## 限制

1. **块级框 ≠ 条款级框**：一个文字块可能含 2–3 行（如「35 履约保证金金额」+ 说明）。真正切到单条条款要版面结构识别，这轮没做。
2. **挑块靠字面重合**：检索词和块没有共同字时退化成「最矮的块」，可能指偏。行文本（抽取出的条件）比检索词更贴题，下一轮可以让 ref 用行文本二次挑块。
3. **`bbox_kind` 目前只记录不作为门禁**：等有一份基线后，再把「page 档占比上升」纳入判红。
4. `page_height` 取自 PDF 页对象；扫描件或异常页高会落到 842pt 默认值，因此判「整页」会有少量误判。
