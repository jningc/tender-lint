# 校验段（阶段 4）

四段里的最后一段：**只看证据够不够，不判合不合理**。全部机械检查，不调模型。

## 四条检查

| 检查 | 判什么 | 失败时 |
|---|---|---|
| `page_exists` | 页码在 1..page_count | 该行判「人工看」 |
| `text_contains` | 条款里抠出的数值，能在引用页原文里找到 | 判「人工看」 |
| `cross_ref_section` | 「详见第X章」的那一章真实存在 | 判「人工看」 |
| `table_exclusive` | 履约/质量保证金不属于废标条件 | 从废标表**移出**，记进 dropped |

外加一条行级扫描（`scan_exclusive`）：**按行扫，不按 finding 扫**。原因是 44% 的行没有 bbox，进不了契约也就成不了 `Finding`——只查 finding 会让整批行逃过校验。崇左那条「履约保证金：中标金额的5%」就是这么漏了两轮的。

## 数值归一

`8000 元` / `8,000` / `0.8 万元` / `捌仟元` 视为同一个数。实现：

- 正则抠 `数字 + 万/元`、`百分比`、`天/日历天`、中文大写金额；
- 中文数字转换只覆盖 `捌仟` / `壹万` / `壹仟贰佰` 这类常见写法，别的返回 `None`，不硬猜；
- 比对时先去掉空格和千分位，再比数字、比「万元写法」、比抠出来的数值集合。

条款里抠不出数值的，`text_contains` 记「无可比对数值，跳过」并算通过——**不因为没数字就判错**。

## 限制（要能说清）

1. **只覆盖有数值的条款**。纯文字条款（如「具有独立承担民事责任的能力」）`text_contains` 直接跳过——没有可比对的东西，不算验证过。
2. **bbox 缺的行只能受行级规则约束**（`table_exclusive`），证据类检查（`text_contains`/`cross_ref_section`）进不去。这是 bbox 那一轮要还的债。
3. **`table_exclusive` 是启发式**：原文写明「不提交即无效」或已判「不满足」就保留。阶段 5 要把它挪进规则库，带触发条件与可审改的记录。
4. **不判语义一致性**：p8 说 8000 元、p17 说 800 元，两处都查得到原文就都通过；冲突识别不在这一段的职责里。
