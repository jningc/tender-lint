# 回归门禁（阶段 3c）

同一个版本跑 **3 次**，每题取多数，和上次比；掉了就 `exit 1`。

## 为什么不能只跑一次

同一份 wenling、同一引擎、同一索引、同一天：**5/5 → 4/5 → 3/5**。行数 68↔83。单跑比分对比会把「没改行为」判成退化，也会把「真改坏」碰巧放过。

## 口径

| 概念 | 定义 |
|---|---|
| 多数票 | 一题 3 次的结论里取多数；2:1 也算多数 |
| flaky | 3 次不一致的题（含 1:1:1 的 `unstable`），**不参与判红**，但要列出 |
| 稳定题 | 去掉 flaky 后的题集；判红只用这组的分母 |
| ★ 对账 | 每份文档「star 行引到的标记页数」取中位数；判红看三份合计，不看 star 行数（同一份文件行数都能 5↔1） |

## 用法

```bash
# 3 次 × 3 份（约 2.5 分钟；文档并发 2、表内并发 6、LLM 并发闸 4）
env -u PYTHONPATH ~/miniforge3/envs/report-rag/bin/python eval/run_regression.py --engine v2

# 改完提示词/规则、确认这次结果是新的正确值时，认成基线
... eval/run_regression.py --engine v2 --update-baseline

# 只跑一份、少跑几次（排查用，别拿来判红）
... eval/run_regression.py --engine v2 --docs beijing_road --repeats 1
```

产物：

```
eval/regression/last.json          当前基线（多数结论 + 计数 + markers），进 Git
eval/regression/run-<时间戳>.json  每次的历史留档，进 Git
data/regression/<时间戳>/<doc>/r<N>.json   每次的六表原件，不进 Git
```

## 判红规则

与 `last.json` 相比，任一条成立即 `exit 1`：

1. 稳定题正例命中数下降；
2. 稳定题负例命中数下降；
3. ★ 覆盖标记页合计下降。

`--update-baseline` 时不判红，直接把这次写成新基线。

## 当前基线（v2 + 条款树（编号族+栈）+ 三类 chunk，3 次，2026-11-24）

| 项 | 数值 |
|---|---|
| 正例 | **14/18**（稳定题 13/17） |
| 负例 | **2/3**（稳定题口径 2/2） |
| 负例违规 | **0** |
| flaky | 2（`wl-bond`、`wl-neg-perf-bond`） |
| ★ 覆盖标记页 | **3**（beijing 0、chongzuo 1、wenling 2） |
| 证据定位 | **页码 + 条款编号**（不统计框粒度；2026-11-23 起 bbox 只用于解析层几何判定） |

三条与旧基线（16/18、★2，段落切分 + 块级 bbox）的差异，都是**口径变了不是退步**：

1. **切分单位从段落改成条款**：段模式 380 字拼段天然覆盖广，条款模式一条一 chunk 更准但更容易漏（`cz-format-bid-sheet`、`wl-validity` 是长期掉的两题）。
2. **索引里多了两类 chunk**（前附表条目 `kind=frontmatter`、评分表行 `kind=table_row`），正例没掉但 `k` 名额被分走，负例出现 flaky。
3. **★ 覆盖从 2 升到 3**：条款树层级修正后，带 ★ 的条款被正确归到章下，覆盖页数这才对得上。

点数在 13–15/18 之间摆动，是模型抖动 + 温岭结构最碎，不是代码行为。

## 比较口径：只在「两次都稳定」的题上比

第一版门禁拿 `pos_stable_hit` 总数直接比。结果块级 bbox 那一轮被判红——因为温岭有 4 题变成 flaky，稳定分母从 16 缩到 14，分数自然从 15 掉到 12，**分母变小被当成了代码退化**。

现在改成：

1. 取两次运行里**都不 flaky** 的题（交集）；
2. 在交集上逐题比上次结论和这次结论；
3. 掉了几条就报哪几条题号，全量多数只作参考。

```bash
# 用已有结果重判，不重跑模型
python - <<'PY'
import json, sys; sys.path[:0] = [".", "eval"]
import run_regression as rg
cur, base = (json.load(open(f)) for f in ("eval/regression/last.json",
                                          "eval/regression/run-20261115-202011.json"))
print(len(rg.common_stable(cur, base)), "条共同稳定题；门禁:", rg.gate(cur, base) or "通过")
PY
```

重判结果：16 条共同稳定题，正例 12 → 12、负例 3 → 3，掉的题 0 条，门禁通过。
（2026-11-24 起共同稳定题数是 17，正例 13/17、负例 2/2。）
测试里留了 `test_gate_ignores_shrinking_stable_set`，防止以后再把分母漂移当成退化。

## 限制

- **repeats=3 仍会平票**（如 hit/miss/absent 各一），这种题记 `unstable` 并归入 flaky；严重程度要用 `--repeats 5` 才看得准。
- 门禁只判「比上次差不差」，不判「够不够好」——绝对值靠 `eval/baseline` 和简历口径另行说明。
- 一轮 146 秒里约 1/3 是载索引和 embedding，同进程重复跑会摊薄。
- LLM 并发闸（`TENDER_LLM_CONCURRENCY`，默认 4）是必须的：表内 6 并发 × 文档 2 并发 = 12，曾把账号的并发额度打爆（429，limit 5）。

## 验证它真的会红

```bash
# 单测直接验比较逻辑
env -u PYTHONPATH ~/miniforge3/envs/report-rag/bin/python -m pytest tests/gate/test_regression_gate.py -q
```

`test_gate_flags_drops` 覆盖「正例/负例/★ 覆盖」三项同时下降时给出三条原因。
