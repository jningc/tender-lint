数据来源：`sample/` 三份政府采购公开招标文件，用 `parse_pdf` + `split_sections` 切出来的实际章节。
外部规范（财政部 87 号令等）本轮**没有抓到原文**（搜索后端限流），所以不引用条文，只报实测。

## 二、合并出来的「常见结构」

| 序 | 章 | 三份里出现的次数 | 占比 | 里面装什么 |
|---|---|---|---|---|
| 1 | 投标邀请 / 招标公告 | 3/3 | 3–6 页 | 预算、最高限价、资格要求摘要、截止与开标时间、获取文件方式 |
| 2 | 投标人须知（含前附表） | 3/3 | 12–20 页 | 保证金、有效期、密封签章、**无效投标情形**、澄清与修改 |
| 3 | 资格审查 | **1/3** | 3 页 | 资格证明材料清单（另两份塞在须知/邀请里） |
| 4 | 评标办法 | 3/3 | 4–10 页 | 评分项、分值、评分标准、**符合性审查（投标无效情形）** |
| 5 | 采购需求 | 3/3 | 8–14 页 | 技术规格、服务要求、数量、**「否则投标无效」的技术条款** |
| 6 | 合同文本 | 3/3 | 4–25 页 | 付款、履约保证金、违约责任、验收（履约阶段约束） |
| 7 | 投标文件格式（含附件） | 3/3 | **24–42 页** | 投标函/开标一览表/声明函等**空表模板**、附件 1–8、格式要求 |

顺序上三份基本一致（邀请 → 须知 → 资格 → 评标 → 需求 → 合同 → 格式），只有崇左把「采购需求」提到了须知前面。

## 三、三个对检索有直接影响的结论

### 1. 资格审查不能当独立依赖

三份里只有北京把它单独成章，崇左和温岭都并进了投标人须知/招标公告。所以「资格条件」的检索范围必须是 `notice + invite + qualify` 三章一起，只搜 `qualify` 在两份文档上会 0 召回。

现在的 `node_feibiao` 正好是这个组合，不用改。

### 2. 格式章是最大的章，而且藏着废标条款

格式章占全文 26% / 40% / 39%，是最大的。里面不只是空表模板，还有真废标条件（实测）：

```
beijing p69  「不得对应当填写的空格不填写或不实质性响应，否则投标无效」
beijing p88  「合同条款偏离情况（应进行选择，未选择投标无效）」
chongzuo p70 「盖章处须加盖联合体各方公章…否则投标无效」
chongzuo p79 「法定代表人必须在授权委托书上签字，否则作无效投标处理」
```

所以「废标」表的检索范围要包含 `format`（含附件）。附件不是独立章——北京的附件 1–8 在第七章内，温岭的在 p51–64，都落在格式章里。

### 3. 章名不统一，别名表得覆盖

| 类型 | 实际出现过的章名 |
|---|---|
| 须知 | 投标人须知 / 投标人须知前附表 / 投标人须知第一节投标人须知前附表 |
| 评标 | 评标程序、评标方法和评标标准 / 评标方法及评分标准 / 评标办法及评分标准 |
| 合同 | 拟签订的合同文本 / 政府采购合同主要条款指引 |
| 格式 | 投标文件格式 / 投标文件格式附件 |

`sections.py` 的 `TYPE_ALIASES` 现在覆盖了这些（实测三份全部切对），但**新文件里可能出现「磋商须知」「谈判须知」「采购需求书」这类变体**——竞价/磋商/竞谈文件用的词不一样。扩样本时要补别名。

## 四、对 B1-a 的直接结论

| 表 | 检索范围 | 依据 |
|---|---|---|
| 废标 | `invite + notice + qualify + score + demand + format` | 实测漏召回：评标办法 6/10/3 条、格式章 4/6/0 条、采购需求 3/3/2 条 |
| 评分 | `score` | 评分标准只写在评标办法，三份都是 |
| 材料 | `notice + qualify + format` | 证书清单在须知和格式章 |
| 空位 | `format` | 空表模板只在格式章 |
| 时间 | `invite + notice` | 截止/开标时间只在公告和须知 |
| 合同 | `contract` | 履约阶段约束，不参与废标判定 |

**合同章不扩进废标**：三份里合同章命中的「拒收/违约金」全是履约违约，不是投标无效（实测 0/1/1 条）。
