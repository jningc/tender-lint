# 规则库里放什么

先想清楚"什么该进库、什么不该"，否则规则库会变成第二个提示词垃圾桶。

## 一、三条准入判据

一条知识能进 `data/rules.yaml`，必须同时满足：

1. **是领域知识，不是机械检查**——换一份招标文件会变、需要人读文件才写得出来的判断。
2. **能指到证据**——哪份 PDF、哪一页、哪道题暴露了它。指不到的规则不入库（防"凭想象加规则"）。
3. **能被门禁复现**——删掉它，某道题的结论从命中变失败；加回来又命中。做不到就不是规则，是聊胜于无的提示词。

三条都不满足却硬塞进去的，就是将来解释不清的负债。

## 二、不进库的（现在清楚划出去）

| 东西 | 为什么不进 | 该在哪 |
|---|---|---|
| 页码存在、bbox 原文含值、交叉引用落章 | 纯机械，换文件也一样 | 校验段 `verify_stage.py` |
| 无页码 → 判「人工看」 | 同上，不依赖领域知识 | `tables.py:force_manual_if_no_page` |
| 六表字段结构、四值判定取值域 | 是契约，不是判断 | `contracts.py` |
| 检索章节范围（废标只搜邀请+须知+资格） | 是检索参数，改了要重测召回 | 现留在 `workflow.py`，可配置化但不进规则库 |

一句话：**规则库只放"两句话说的是不是同一件事"这类知识。**

## 三、格式

```yaml
version: 1
rules:
  - id: bond-family
    kind: exclusive              # exclusive | synonym | mapping | classifier | unit
    scope: [extract, compare]    # 只有这两段读；parse/verify 不读
    when:
      terms: ["履约保证金", "质量保证金"]
      table: 废标对照
    unless:
      any_text: ["不提交即无效", "投标无效", "废标", "拒不提交"]
      verdict: [不满足]
    then:
      move_to: 合同要点
      log: "bond_not_bid_bond"
    evidence: "chongzuo p26 前附表 35「履约保证金：中标金额的5%」；题 cz-neg-perf-bond"
    since: 2026-11-15
    test: "cz-neg-perf-bond：期望 violated → hit；bj/wl 同样三条负例不放宽"
```

四个字段是硬要求：`evidence`（可指到页）、`test`（可映射到题）、`scope`（哪段读）、`kind`（怎么被消费）。缺一个就不合入库。

## 四、首批候选（按证据强度排，不是按想法排）

### R1 `star-marker`：★/▲ 什么时候算实质性条款

- **证据**：崇左 ★22 + ▲8 散在 10 页，但 p19/p20 的 ★ 是**政府采购品目清单代码**（`★A02010104 台式计算机`），不是条款；北京 p26 的 ★ 出现在符合性审查项名「★号条款响应」里，也不是被标记的条款。
- **现状**：`workflow.py:35` 一条正则 `[★▲＊*]`，只在废标节点命中的三章里找，命中一条就 `break` → 崇左 30 个标记只出 1 行，北京 p26 完全没进表。
- **规则**：★/▲ 只有出现在**条款正文前缀**（行首，后接条款号或汉字正文）才算实质性条款；后接 8 位品目代码、在引号内、或在表头/审查项名里都不算。
- **测**：★ 覆盖标记页 2/16 → 目标 ≥8/16；且不得把品目清单行塞进废标表（负例 cz-neg-perf-bond 的同类检查）。
- **为什么排第一**：这是当前唯一"按字符判必然错"的硬伤，且改动可量化。

### R2 `bond-family`：保证金三兄弟互斥

- **证据**：崇左 p26 前附表 35「履约保证金：中标金额的 5%」被 v1/v2 塞进废标表；北京 p8 的 8000 元是投标保证金、p83 是履约保证金。
- **现状**：`verify_stage.scan_exclusive()` 里硬编码关键词 + `workflow.py:325` 一句提示词警告。规则藏在两处，改一处漏一处。
- **规则**：投标保证金 → 废标对照（不交即无效）；履约/质量保证金 → 合同要点；只有原文写明"不提交即无效"才进废标表。
- **测**：三份各一道负例（`bj-neg-perf-bond`、`cz-neg-perf-bond`、`wl-neg-perf-bond`）——**一条规则顶三道题**，最划算。

### R3 `qualification-level`：资质等级的包含关系

- **证据**：北京 p25 要求总监「市政公用工程」专业，公司是「房屋建筑」→ 判不满足（`bj-director`）；崇左要求「市政公用工程施工总承包三级及以上」，公司缺该资质。
- **现状**：全靠模型读公司 yaml 自由判断，没有等级比较逻辑。
- **规则**：同专业下 一级 ⊃ 二级 ⊃ 三级（有高等级可投低等级要求）；专业名必须一致（房屋建筑 ≠ 市政公用）；「施工总承包」与「专业承包」是并列序列，不互相包含。
- **测**：`bj-director`（专业不符→不满足）、`cz-bond`（缺资质→不满足）；再加一条"公司有二级、要求三级→满足"的反向题，才能证明不是一律判不满足。

### R4 `credential-alias`：证书/岗位同义

- **证据**：北京原文写「总监理工程师（市政公用工程专业）」，题面写「总监」；崇左写「专职安全生产管理人员」，俗称「安全员」。
- **规则**：总监理工程师 = 总监；注册建造师 = 一级建造师 = 一建；专职安全生产管理人员 = 安全员（C 证）；职称与执业资格不互换。
- **测**：`bj-director`、`cz-bond` 的检索命中率；同义表还能减少"公司明明有、判成没有"。

### R5 `time-unit`：日历天 ≠ 工作日

- **证据**：北京 p8 13.1「自提交投标文件的截止之日起算 90 日历天」；温岭、北京各一道有效期题（`bj-validity`、`wl-validity`，后者还常 flaky）。
- **规则**：日历天按自然日算，工作日排除节假日；原文没写单位时按日历天并降「人工看」。
- **测**：`bj-validity`、`wl-validity` 从 flaky 变稳定才算生效。

### R6 `money-normalize`：金额与比例的写法归一

- **证据**：北京 p8「8000 元」、崇左 p26「中标金额的 5%」、公司 yaml 里「注册资本 1000 万元」。
- **现状**：`verify_stage` 已实现（8000 / 8,000 / 0.8万 / 捌仟），但只有校验段在用；抽取段比对注册资本时没有同一套折算，容易把「壹仟万元」和「1000 万元」当两回事。
- **规则**：同一套归一函数给抽取/比对/校验三段共用；百分比三种写法（5%、0.05、百分之五）等价。
- **测**：构造一条「要求注册资本 1000 万元、公司写壹仟万元」，判满足。

### R7 `agency-checked`：代理机构代查 → 无须提供

- **现状**：只在 `workflow.py:250` 一句提示词里。
- **缺什么**：**我还没在样本里核实到一页明确依据**——比如「由采购代理机构通过信用中国查询」这类句子在哪页、原文怎么写的。做这条之前必须先人工找到那页，找不到就不入库（按准入判据 2）。

### 不进候选的一条

「评分表只有 `estimate`、不给 `verdict`；空位/时间/合同是事实项」——这是表的形状，属于契约，写进规则库反而会让"删规则分数掉"的实验失真（删了表就崩，不是判断错）。

## 五、落地顺序与验收

| 步骤 | 动作 | 期望 |
|---|---|---|
| A | 现状跑门禁（规则库空，只是把硬编码搬进 YAML 但不启用） | 与当前基线一致（14/18、负例 2/3、★3；见 `docs/规则/回归门禁.md`） |
| B | 启用 R2 | 三份负例稳定 3/3；`cz-neg-perf-bond` 稳定 hit |
| C | 启用 R1 | ★ 覆盖页 2/16 → ≥8/16，且废标表不混入品目代码 |
| D | 删掉 R2 再跑 | `cz-neg-perf-bond` 回到 violated —— **这一步是规则真的在起作用的证据** |
| E | 启用 R3/R4 | `bj-director` 稳定 hit；新增反向题（有二级投三级）判满足 |

B 和 D 必须各跑一次 3×3（约 160 秒/次），数字写进 `docs/规则/回归门禁.md`。A/B/C/D 四次结果是简历上"退化 → 回滚"那段的素材，不能只留结论。

## 六、注入方式（为什么它能被门禁测到）

规则不能只是"渲染进提示词的建议"，那样删了也测不出差别。每条规则要有两条实现：

1. **代码侧**：抽取/比对段读完 YAML 后过滤或改写行（如 `bond-family` 把履约保证金行从废标表移到合同表）；
2. **提示词侧**：同一条规则的一句话版本附在对应节点后面，减少模型自己犯错。

门禁只改代码侧就能变红，才算规则生效。
