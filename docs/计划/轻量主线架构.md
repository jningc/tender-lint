## 一、一句话

**主路径：结构取数 + LLM 填固定表 + 机械校验 + 回归门禁。**  
**旁路：工具 Agent 问答。**  
**检索：按章 hybrid（BM25 + 向量 + RRF），服务旁路和追引用，不当覆盖率保证。**

## 三、和「重架构」的边界

| 重（输出驱动全做）      | 轻（本主线）                                                                            |
| -------------- | --------------------------------------------------------------------------------- |
| 六块事项 × 层 YAML  | **至多 1 张卡**（投标保证金）演示多源合并                                                          |
| 短条款全过 + 真三态落地  | **口述三态**（未写明需要覆盖记录）；代码可不做或只做有值/待人工                                                |
| 检索彻底退出主路径      | **仍走** `search` **的只有 3 张**：废标、材料、合同；评分（表直读）、时间（正则）、空位（改并入材料）已脱离检索。**叙事上**检索不保证覆盖 |
| 改全题集迁就新输出      | **门禁维持可用**；新指标只加切句/前附表计数                                                          |
| B4-c / B4-d 全做 | **冻结**（面试后或入职后再开）                                                                 |

**B4 的论点要讲，全量实现不必做完。** 细是加分；把细全写成代码，在应聘阶段是负担。

## 四、四块能力怎么挂

| 能力 | 落点 | 面试怎么说 |
|---|---|---|
| **RAG** | 按章索引、条款 + 父路径 context、表 small-chunk、**RRF**（`TENDER_FUSION=rrf\|union`） | 混合检索做对了；并说清**何时不用 top-k 保清单覆盖** |
| **LLM** | 结构化六表、重试 / 并发闸、无抓手删除 | 固定 schema IE，不是聊天 |
| **Agent** | `ask_box`：4 工具、≤5 步、强制取证、有 trace；**评测 5/5、平均 2.0 步、全部调工具** | 旁路 agent；主路径选固定流水线是有意的。演示题见 `eval/ask_cases.json` |
| **Harness** | 回归门禁、flaky、三次多数、基线对比、bbox 口径 | 强项；卡住幻觉与退化 |

岗位心结：**不必把主线改成企业知识库/客服问答才算 LLM 岗。** 固定 schema IE + 旁路 Agent + harness，比再做一个 Contextual+RRF 知识库更不套、也更好讲「系统边界」。事项穷尽是加分判断，轻量只做迷你切片即可。

## 六、面试开口（约 20 秒）

> 这是招投标固定 schema 核对，不是知识库聊天。主路径用结构直读和定位，LLM 结构化填表；旁路是 tool-calling Agent；用校验和回归 harness 卡住幻觉。检索（hybrid，RRF 可开关）给追引用和 Agent——问答可以 top-k，清单覆盖要可证明看见；后者目前落地了「无抓手不落表」，完整层覆盖是设计，迷你 B4 用保证金一张卡演示多源。

**时态：**「可证明看见」= 设计目标 + 半落地；被追问主动说，见第四·二节。自进化（规则库）纠的是「看见之后少判错」，**不能替代**直读/穷尽负责的「看见」。
