# 评分规则的两种载体（坑 2）

> 和 `docs/计划/表格检索方案.md` 是同一条表线的续篇。
> 那篇解决「表抽出来之后怎么检索 / 怎么喂抽取」；本篇只谈：**表抽对了，写在正文里的评分规则仍然会丢。**
> 坑 1（建索引两条入口）已在默认 v2 + `parse_stage` 收口里修掉，见该文档第六节「接入时踩的两个坑」第 2 条。本篇只处理第 1 条。
> 代码：`tender/workflow.py` 的 `node_pingfen` 已按第四节改（章内公式扫描 + 项名去重；原 BM25 query 仍作双保险）。

---

## 一、问题是什么

评标办法里的评分规则有两种承载形式，不是一种：

| 载体 | 长什么样 | 抽取单位 |
|---|---|---|
| **表格** | 评审因素 × 分值 × 评分标准（可跨页、可合并格） | 一行 = 一个评分项 |
| **正文** | 计算公式、低价优先法说明，写在表前/表后的段落里 | 一条公式 / 一段办法 |

表线接入 `node_pingfen` 之后，有表就只喂整表 HTML。第二种载体不在表里，模型看不见，对应评分项就不会进「评分对照」。

三份样本里最典型的是温岭：p19–21 是评审表，价格分公式单独写在 **p18 正文**：

```
投标报价得分=(评标基准价／投标报价)×50%×100
```

北京的公式在 p33 表格单元格里，表线能吃到；崇左公式在跨页表续页（p47），抽表接上了也能吃到。所以这个问题不是「所有文档都会炸」，是 **公式一旦离开表格网格就丢**。

## 二、在哪查出来的

不是设计评审里想出来的，是 **表线接入主流程之后的回归门禁** 查出来的。

出处：`docs/计划/表格检索方案.md` →「接入时踩的两个坑」第 1 条；题集 `eval/questions.json` 的 `wl-price`。

| 项 | 内容 |
|---|---|
| 题 | `wl-price`：评分对照须命中「评标基准价」，页码 **p18** |
| 接入表线前 | 走条款检索，能扫到 p18 |
| 接入表线后（只喂表） | 只看见 p19 起的表，p18 不在 prompt 里 → `wl-price` **miss** |
| 第一轮门禁 | 正例 **12/18**（掉的就是它） |
| 当时的补丁 | 抽完表再 BM25 一次：`价格分 报价 评标基准价 计算公式 满分`，按项名去重 |
| 补丁后 | 温岭日志会出现「表外补充 1–3 条」；门禁回到 14/18 |

补丁证明了「表外确实有规则」，但实现仍是一句写死的 query、且 **只有认出评分表时才补**。这就是坑 2 还没从架构上关掉的原因。

## 三、思考过程

### 1. 先排除「再写解析」

正文公式不是缺表格结构识别。PyMuPDF 已经把 p18 抽成文字块了；丢的是 **抽取入口没把这些块当评分规则的一等公民**。继续加深表格解析解决不了。

### 2. 两种「补正文」的候选

| 做法 | 判断 |
|---|---|
| 有表也始终再跑一轮评分条款 BM25（加长 query） | 能覆盖无公式的文字项，但短公式词频弱，k 一大还脏 |
| **评标办法章内按公式符号扫** | 对 `wl-price` 这类最对症：等号 + 乘号/除号 + 报价/基准价 |

三份样本的表外价格分都长得像算式，不是散文。符号是硬特征，和 ★ 全章扫描是同一类「不要靠 top-k 碰运气」。

### 3. 符号不能裸搜

只搜 `×`、`=`、`%` 会误伤「有效期 90%」「保证金」等。必须同时满足：

- 范围只限 **评标办法章（`score`）**，不扫须知/合同；
- 一行里有 `=`/`＝`，且有 `×`/`／`/`/`；
- 附近有 `报价` / `基准价` / `价格分` / `得分`。

命中块直接当表外 `hits` 喂现有抽取，按评分项名与表结果去重。

### 4. 符号扫覆盖不了什么

没有公式的文字评分项（纯段落「商务分按业绩给」）符号帮不上。那是 BM25/条款检索的事，不要和公式兜底捆成一次提交。符合性审查（「投标无效」）属于废标表 / B1-a，**不要塞进评分对照**。

### 5. 和表格检索方案怎么分工

```
抽表 tabular.py          → 网格、跨页、合并     （表格检索方案 第 1 步）
small chunk TableIndex   → 问答侧定位哪一行     （表格检索方案；抽取不用）
整表 HTML → node_pingfen → 评分项全量抽取       （表格检索方案「接进主流程」）
score 章公式扫描         → 表外计算公式          （本篇）
按项名去重后合并
```

抽取要的是全量，所以公式扫描是 **给抽取垫候选**，不是用 small chunk 代替整表。

## 四、解决方案

只改 `tender/workflow.py` 的 `node_pingfen`（一次一个变量）：

1. **有评分表**：仍逐表喂 HTML（不动）。
2. **无论有没有表**：在 `score` 章对块/条款做公式符号扫描，命中则再抽一次「表外评分规则」。
3. **按 `item` 去重**：表里已有的项，正文只补没有的（现成 `item[:12]` 逻辑可留）。
4. 现有 BM25 那句价格分 query **可以先留作双保险，下一轮再删**，避免和「改成符号扫」两个变量混在一起说不清。

日志必须能看见：`按表抽取（N 张）` 以及 `表外补充 M 条`（M=0 也打），避免再静默丢。

### 验收

- `wl-price` 稳定 hit，页码落到 p18（或公式所在块）。
- 北京 `bj-price` 不因正文扫描再长出一条重复的「投标报价」。
- 门禁 3×3：正例不低于接入表线后的 **14/18**，负例 **2/3**（2026-11-24 现状；`wl-neg-perf-bond` flaky，稳定题口径仍是 2/2）。
- 不把符合性审查行灌进评分对照。

### 明确不做

- 不上新的版面/公式解析模型。
- 不把 `TableIndex` 接进抽取。
- 不和 ★ 扫描、扩废标检索范围同一提交。
