# 对《检索与扫描架构》的审阅

> 2026-11-21。对象：`docs/计划/检索与扫描架构.md`。对照该文档、此前关于短条款/扫描/ToM 的讨论，以及仓库实现（`workflow.py`、`extract_stage`、`compare_stage`、门禁 `eval/regression/last.json`）。
>
> 结论先行：**方向适合作为架构转向；不适合按第五节原样当 ToM/MapReduce 施工说明书。**

---

## 一、总评：适不适合

**适合作为判断：** 六张表是固定 schema 的信息抽取，不是问答；用检索 top-k 做抽取，覆盖率天然不可控。L3（按表分流）和第六节时间实验，比只调 BM25 的 `检索改造方案.md` 更贴这个项目。L1/L2 降级成「检索还活着才做」也正确。

**不适合照第五节原样开工：** 文档要做的其实是 **按章打包的全量抽取 + 代码去重**，不是论文里的树形 MapReduce。验收指标会虚高；废标/材料全量 LLM 会放大已经踩过的「长得像废标」，并拉高门禁耗时。

---

## 二、事实错误、口径混用

**1. 门禁 15/18 和别的文档打架。**  
`eval/regression/last.json` 是 **pos_hit 15/18、稳定 14/17、flaky 含 `wl-bond`**。`任务总顺序.md` 写 14/18，★ 有的地方 1、有的地方 2。用 15/18 可以，但必须写清是「三次里出现过 hit」还是「多数票」。否则第七步「重做题集」会和现网门禁对不上。

**2. 「评分对照 100%、调用成本 0」不成立。**  
表结构召回 5 张 35 行是 A1 的几何指标。`node_pingfen` 仍把整表 HTML 送给模型抽 `PingfenTable`，没有表时还走检索；表外公式已经在 `_formula_hits` 里扫。直读 ≠ 零 LLM，也 ≠ 评分表已经抽完。坑 2（散文公式）这篇几乎没写进路由表。

**3. `top-8` 覆盖 524 条款的 1.5%。**  
条款数在 `任务总顺序` 里是 **592 / 514 / 398**，524 是旧口径。更关键的是：废标并不在全书条款上检索，只在 `invite/notice/qualify/score/demand` 里取 k=8。用「全书条款分母」夸大了检索的覆盖缺陷（缺陷仍在，数字过满）。

**4. 时间 82%、17 处、漏 3→0，页和「处」混在一起。**  
`eval/time_scan.py` 比的是 **正则命中页 ∩ 表里的页**，不是 17 个互斥时间事件。北京表 9 行/9 页，未覆盖 7 页再分成「3 处投标期 + 4 页履约」。`17 处、漏 18%` 是拼出来的。  
另外，`CONTEXT` 里没有 **「解密」**，而门禁稳定 miss 里有 `bj-decrypt`。即便正则进表，按现在词表也可能扫不到解密。

**5. 题集不是「按检索能不能命中」设计的。**  
`eval/questions.json` 是业务点（保证金、限价、开标一览、负例履约保证金），判的是 **抽出来的表行/页**，不是 retriever 的 hit。检索是实现手段。说 21 题无法回答「全书还有多少废标句没进表」成立；说题是为检索设计的，不成立。

**6. `chunk_clauses` 的注释和实现。**  
文档写「父标题链 + 本条」对；`index.py` 里函数注释还写着「同编号前缀兄弟」。不要引用过时注释。BM25 只索引 `text` 这句是对的。

## 三、内部矛盾

**第七步第 1 条 vs 第六节。**  
第六节结论是：时间表 **不需要全扫**，该改字段结构（投标期/履约期）。实施却写「加 `阶段` 字段，漏 3 → 0」。加字段只会把履约 4 页 **划走**，不会把 p16/p20/p28 **补进表**。那 3 处要靠「正则命中写进行」，和「不需要全扫」可以同时成立，但必须写成两步：拆阶段 + 用已有 `time_scan` 补漏。现在「漏 3→0」是假验收。

**L3 废标不再检索 vs 4.5。**  
4.5 仍用「query 是 `投标无效 最高限价 预算`」论证不换 SPLADE。废标若已退出检索，这条理由只适用于 `ask_box` / `_follow`。4.4–4.5 整段是上一份检索方案的搬运，和「检索降级」并列，读起来像还要先调 BM25。

**ToM vs NavTree。**  
ToM：内部节点是 **摘要**，Reduce 用 LLM 消冲突。NavTree：**只有叶子进模型，内部节点只路由**。第五节是「叶子打包进模型 + **代码** Reduce」，更接近 NavTree + LexNLP，不是 ToM。用 ToM 那句「显著优于 RAG」给自己背书过重——既没有 HSP 建树，也没有父节点 LLM Reduce，树还是 `clauses.py` 里已有的编号树。

**Harvey。**  
clause-by-clause 对照 playbook，和「固定 schema 要穷尽」同类，可引。但「旧架构分类→检索证据→结论」是他们 **playbook 多 agent 重写**，不是「信息抽取不要 RAG」的定理。红线产品和抽六张表也不是同一任务（他们对照的是客户标准，这里对照的是 `company.yaml`）。

## 四、方案层风险（按表）

### 废标「章节全扫 + MapReduce」——方向对，形态偏贵、偏险

适合：废标必须穷尽，top-8 不可控；格式/合同不进废标，和已实测违规一致。

风险：

- **没有定位器。** 须知整章打包进 LLM，大部分不是废标句。ContraxSuite/LexNLP 是「正则先标，再抽」；评分公式已经是这条。废标至少应先滤后果/限价/★，再打包，否则成本和「履约保证金」类假阳性一起涨。须知里同样有「中标后提交履约保证金」，**不扫 format 挡不住**。Reduce 的前 20 字去重也挡不住，那是合并重复句，不是类型闸。C1 的 `exclusive_pairs`（投标保证金 ≠ 履约保证金）应写进 Reduce/过滤，原文没提。
- **~10 次调用偏乐观，且会改 v2 假设。** `extract_stage` 注释仍是「六张表各一次」。废标 5 类章 × 8000 字/包 × 重叠 2 条，北京须知一章就可能不止 2 包。`HIT_BLOB_MAX_CHARS = 8000` 曾在 k=12 时让模型返回空结果；现在变成 **多次 8000 字抽取**，失败率和耗时都会上去。文档没写并行、超时、失败包怎么办。
- **Map 之后对照公司谁做。** `FeibiaoRow` 有 `company` / `verdict` / `star`。第五节只抽「条件原文、页、后果」。`compare_stage` 目前 **不调模型**，只搬抽取里已有的 verdict。全扫方案等于被迫提前做「抽/比分离」，工期不是 1–2 天能装进 workflow 的补丁。
- **Reduce 前 20 字。** 「投标人应当…」会把不同义务并成一条；限价和资格共享不了前 20 字又并不上。冲突规则（允许/不允许）对招标后果句几乎用不上。预期去重率 50%–70% 没有业务含义。
- **「pack 覆盖 100%」是 tautology**（包都送进模型了），和第八节批评的「用 evidence.clause 判覆盖必然 100%」是同一类虚指标。覆盖率应是：正则/人工金标句有没有出现在 **最终表** 里，bbox 是否落在条款并集里（`bbox_report` 已有这套）。

**★ 整张路由表缺了。** `任务总顺序` 里 ★ 全章扫仍是未做；废标 Map 提示词只写「投标无效」，★ 句不一定带这些词。不写进第三节，扫描架构是残的。

### 材料全扫

材料在格式章有真清单，也有模板里的「应提交原件」。文档只对废标写了 format 黑名单，材料若扫 format，会重演模板句，只是落在材料表。需要单独写 **types 白名单** 和「模板/填空降权」，不能「同废标一套 MapReduce」。

### 合同「无形态只能全扫」过满

合同要点同样有强字面：金额、期限、`履约保证金`、`预付款`。更像「词表定位 + 一包抽取」，不是无特征。当前节点还搜 `format`（投标函里的履约保证金），和「只扫合同章」不一致，应写死，避免和废标再次串表。

### 空位 `____` / `（  ）`

`cz-format-bid-sheet` 是 **开标一览表**，空格经常是空单元格，不是下划线。结构扫应 **表优先（和评分同一套 `tabular`），下划线作补充**。只扫 `____` 过不了这题。

### 时间正则

实验有价值，结论「强字面用正则」对。补漏应直接吃 `time_scan` 的命中，再让模型（或规则）起名：截止/开标/澄清。加 `阶段` 字段是 schema 事，解决不了 miss。履约期限进合同表可以，但合同表若仍检索，这 4 条还会丢——第六节暗示拆完合同就多 4 条，**没有对应的合同取数改动**。

## 七、建议改原文的几处

1. **标题和 5.x：** 改成「按章打包全扫 + 代码去重」，MapReduce/ToM 放到「不像什么」一小节，避免施工时去实现父节点 LLM。
2. **第三节补列：** 每张表的 `section_types`、要不要正则预滤、现有扫描（公式/★）怎么办；★ 单独一行。
3. **覆盖率定义：** 金标句/页 ∈ 最终表行，且 bbox 条款档；删掉 pack 100%、去重率当验收。
4. **废标 Map 前加定位器**（后果 ∪ 限价 ∪ ★），format/合同继续黑名单，Reduce 加入履约/投标保证金互斥。
5. **时间步拆开：** 拆 `阶段`；正则命中补行；CONTEXT 加解密/开标相关词。不要写漏 3→0。
6. **评分：** 结构直读 + 已有公式扫；成本不是 0。
7. **空位：** 格式章表格行 + 下划线，不要只写 `____`。
8. **实施顺序与 `任务总顺序` 对齐：** 先分流取数，L1/L2/RRF 仅 ask/_follow；写明门禁可能变慢、违规可能先升后降。
9. **数字：** 条款数 592/514/398；门禁写 15/18 hit、14 稳定；评分 35/35 是行召回不是抽表完成。

**一句话：** 架构判断该留（抽取不要靠检索）；施工方案要把「ToM 全量 LLM」收成「字面定位 + 有限打包抽取」，否则最可能出现的不是覆盖率上去，而是门禁变慢、负例再炸、覆盖率还是自说自话的 100%。
