## T0 定口径（0.5 天，纯文档）

现在的「条款级 100%」是**块级**口径（`docs/bbox条款级.md:64` 自己写着）。要往下推进，先把下面四条写死，否则 T2 切完无法验收。

建议值（改完存成 `docs/条款口径.md`，删掉这段说明）：

1. **一条条款的边界**：从一个条款起点行开始，到下一个条款起点行之前。中间的空行、续行、表格都归这条。允许跨页（跨页时记 `page_start/page_end`，bbox 用首块，`continued=true`）。
2. **条款起点判定：先探测档位，再套优先级。** 三份样本实测用了三套不同编号（无编号行都占 76%–83%）：

   | 文档 | 主力档 | 次要档 | 几乎不用 |
   |---|---|---|---|
   | beijing_road | `X.Y.Z` 5.2% + `X.Y` 7.9% | `1.` 4.9%、`（1）` 2.7% | `第X条` 0.8% |
   | chongzuo_green | `1.` 7.8% | `（1）` 5.0%、`X.Y` 5.4% | `第X条` 0 |
   | wenling_video | `1.` 8.8% | `一、` 2.4%、`（1）` 2.6% | `X.Y` 0.7% |

   所以写死一档必错。规则改成：先统计本文档四档的命中率，取命中最多的两档当「起点档」，其余档只在同档位内作辅助；一档都不到 2% 时退回字号规则。
   档位定义（按优先级）：`第X条` > `X.Y.Z` / `X.Y` > `（一）`/`（1）` > `①` > 字号 ≥ 正文最大字号 ×1.1 且独立成行 > 都不满足则**不切**，归上一款并标 `kind=block`。
   **正则必须收紧**：编号后紧跟汉字或空白，否则 `2263.76` 这种数字会被当成 `X.Y`（chongzuo 实测有误报）。
3. **表格按行算**：一个评分项 = 一行；单元格不单独成条款。跨页表：下一页首行若无表头且列数与上页相同，接续为同一张表。
4. **失败回退**：无编号、无字号线索、扫描件 → `kind=block`，仍是条块级框，照旧进表；不进 `人工看`（`人工看` 只留给「没页码」）。

验收：三份样本各挑 2 页（含 1 页评分表、1 页跨页表），人工在纸上标条款边界，拿这四条规则逐条对。规则写不下的地方，说明规则要改，不是页面标错。

顺手改一处：`eval/题集核对清单.md` 里补一句「判分口径从页码级升到条款级时，`expect_pages` 保留，新增可选 `expect_clause`（条款编号）」，为 T2d 留口。

## T1a 术语表 + 同义归一（1 天，不改行为）

**建文件** `ontology/terms.yaml`（放 ontology 是因为它和 `tender.ttl` 同类：都是领域知识，不是代码）。

按六张表的 key_fields 建骨架，与 `tender/tables.py:130-182` 一一对应：

```yaml
feibiao:
  condition:
    投标保证金: [保证金, 磋商保证金, 投标担保, 竞标保证金]
    履约保证金: [履约保函, 履约担保]      # 注意：和上面不是一回事，必须分开
pingfen:
  item:
    价格分: [报价得分, 价格评审, 投标报价分]
cailiao:
  material:
    营业执照: [企业法人营业执照, 三证合一营业执照]
kongwei:
  form: [投标函, 开标一览表, 法定代表人授权书]
shijian:
  name:
    投标截止时间: [递交投标文件截止时间, 投标文件递交截止, 开标时间]
hetong:
  item:
    付款方式: [结算方式, 支付方式, 价款支付]
```

每条的 `标准词` 必须在样本 PDF 里真实出现过（记 `source: <stem>:p<N>`），**不许凭想象加**。这一条是它能不能进简历的分水岭。

**写代码** `tender/terms.py`（约 80 行）：
- `load_terms()` → 缓存 dict
- `normalize(text) -> text`：同义词替换成标准词后返回，供比对用
- `expand_query(q) -> q`：把标准词展开成别名串，供 T1b 用

**写题集** `eval/terms_cases.json`，20 条，三类各占三分之一：
- 同义改写（要求「注册建造师」，投标写「一级建造师」→ 应匹配）
- 方向陷阱（「不得低于 3 年」vs「不超过 3 年」→ 不应匹配）
- 近似但不同（「投标保证金」vs「履约保证金」→ 不应匹配，这是核心防错）

**验收**：`pytest tests/test_terms.py` 全绿；20 条匹配率 ≥ 80%（达不到先扩术语表，别改题）；三份样本回归分数**必须与当前基线一致**（这一步没改检索，分数一动就是有 bug）。

## T2b 条款树切分（2 天，改行为）**切分器完成；索引接入退化，默认关闭**

新建 `tender/clauses.py`：
- `build_clauses(pages, sections, table_boxes) -> list[ClauseNode]`，规则照 `docs/条款口径.md`

**落地记录（实测）**

| 项 | 结果 |
|---|---|
| 条款数（真条款 / 总） | beijing 524/547、chongzuo 487/531、wenling 321/345 |
| 字数中位 | 62 / 60 / 51（段落模式是 380） |

所以切分器可以用，但**必须整轮重调检索**才能启用，见 T4。

## T4 条款单位下的检索重调（1 天，启用 clause 模式前必做）

clause 模式掉分不是切分错，是 `k=6` 和写死的 query 按 380 字段落校准过。三件事按序做，每件单独跑门禁：

1. **放开 k**：条款从 ~400 段涨到 500+ 条，`k` 从 6 提到 10–12（加 `TENDER_TOPK` 环境变量，别写死）。
2. **query 带编号档**：六张表的 query 常量末尾追加该表的编号特征（`第X条 X.Y`），让「编号独占一行」的条款块能被 BM25 命中。
3. **★/▲ 专项扫描**：现在 ★ 靠 top-k 顺带捞到，条款模式下必丢（实测覆盖 2 → 0）。改成全章正则扫 `[★▲]`，直接定位所在条款当兜底——这是 bbox 轮遗留的 TODO。

验收：clause 模式门禁 ≥ 段落基线（正例 16/18、★ 覆盖 ≥ 2），达不到就继续默认 paragraph。

## 一件不做

**不让模型按文件生成提示词。** 提示词是判定标准的唯一载体，一改成每份文件自动生成，`eval/run_regression.py` 的 `last.json` 就失去可比性，整套门禁作废。术语用词差异走 `terms.yaml`（数据），不走提示词（代码）。
