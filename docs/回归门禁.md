# 回归门禁（阶段 3c）

同一个版本跑 **3 次**，每题取多数，和上次比；掉了就 `exit 1`。

## 为什么不能只跑一次

同一份 wenling、同一引擎、同一索引、同一天：**5/5 → 4/5 → 3/5**。行数 68↔83。单跑比分对比会把「没改行为」判成退化，也会把「真改坏」碰巧放过。

## 口径

| 概念 | 定义 |
|---|---|
| 多数票 | 一题 3 次的结论里取多数；2:1 也算多数 |
| flaky | 3 次不一致的题（含 1:1:1 的 `unstable`），**不参与判红**，但要列出 |
| 稳定题 | 去掉 flaky 后的题集；判红只用这组的分母 |
| ★ 对账 | 每份文档「star 行引到的标记页数」取中位数；判红看三份合计，不看 star 行数（同一份文件行数都能 5↔1） |

## 用法

```bash
# 3 次 × 3 份（约 2.5 分钟；文档并发 2、表内并发 6、LLM 并发闸 4）
env -u PYTHONPATH ~/miniforge3/envs/report-rag/bin/python eval/run_regression.py --engine v2

# 改完提示词/规则、确认这次结果是新的正确值时，认成基线
... eval/run_regression.py --engine v2 --update-baseline

# 只跑一份、少跑几次（排查用，别拿来判红）
... eval/run_regression.py --engine v2 --docs beijing_road --repeats 1
```

产物：

```
eval/regression/last.json          当前基线（多数结论 + 计数 + markers），进 Git
eval/regression/run-<时间戳>.json  每次的历史留档，进 Git
data/regression/<时间戳>/<doc>/r<N>.json   每次的六表原件，不进 Git
```

## 判红规则

与 `last.json` 相比，任一条成立即 `exit 1`：

1. 稳定题正例命中数下降；
2. 稳定题负例命中数下降；
3. ★ 覆盖标记页合计下降。

`--update-baseline` 时不判红，直接把这次写成新基线。

## 当前基线（v2，3 次，2026-11-11）

| 项 | 数值 |
|---|---|
| 正例 | 15/18（稳定题 14/16） |
| 负例 | 2/3 |
| 负例违规 | 1（`cz-neg-perf-bond`：履约保证金仍混在崇左废标表） |
| flaky | 2（`wl-bond`、`wl-validity`） |
| ★ 覆盖标记页 | 2/16（beijing 0、chongzuo 1、wenling 1） |
| 单轮耗时 | 146s（54 次模型调用） |

`wl-bond` 和 `wl-validity` 三跑不稳，正说明温岭那两份题只能当采样看；要稳定它们得先修检索/抽取，不是改题。

## 限制

- **repeats=3 仍会平票**（如 hit/miss/absent 各一），这种题记 `unstable` 并归入 flaky；严重程度要用 `--repeats 5` 才看得准。
- 门禁只判「比上次差不差」，不判「够不够好」——绝对值靠 `eval/baseline` 和简历口径另行说明。
- 一轮 146 秒里约 1/3 是载索引和 embedding，同进程重复跑会摊薄。
- LLM 并发闸（`TENDER_LLM_CONCURRENCY`，默认 4）是必须的：表内 6 并发 × 文档 2 并发 = 12，曾把账号的并发额度打爆（429，limit 5）。

## 验证它真的会红

```bash
# 单测直接验比较逻辑
env -u PYTHONPATH ~/miniforge3/envs/report-rag/bin/python -m pytest tests/test_regression_gate.py -q
```

`test_gate_flags_drops` 覆盖「正例/负例/★ 覆盖」三项同时下降时给出三条原因。
