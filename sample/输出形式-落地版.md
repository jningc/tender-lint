# 输出形式（落地版）

> 补充 `输出形式.md`，不替代它。那份讲「按投标人要办的事分」，这份把它拆成**字段 + 规则 + 校验**，能直接对着写代码。
>
> 版式示意来自 `scratch/output_preview.html`，数据是 `beijing_road.pdf` 的真实抽取结果（compare.findings + p33 评分表 + time_scan）。

---

## 一、整份结果长什么样

```
┌──────────────────────────────────────────────────────────┐
│ 北京东城道路监理 · 招标文件核对                             │
│ beijing_road.pdf · 92 页 · 核对时间 …                      │
├──────────────────────────────────────────────────────────┤
│ ● 2 项硬伤   1 资格门槛不满足   5 必废风险   6 需确认        │
│              投标截止 2026-08-18 09:00                    │
└──────────────────────────────────────────────────────────┘

① 能不能投   资格门槛 4 条        ← 对照 company.yaml
② 会不会废   无效情形 11 条       ← 按确定性分档
③ 交什么     材料 8 项            ← 附证明 / 代查 / 需填表
④ 得多少分   → 30 + 商 10 + 技 60 ← 客观 / 主观
⑤ 什么时候   时间轴 4 点 + 4 个时长
⑥ 中标后     合同要点 5 项        ← 有值 / 未写明 / 待人工
```

**结论条不进表格，单独一行。** 六块并列时用户要自己拼「所以我能不能投」，结论条是这个报告唯一必看的东西。

---

## 二、结论条怎么算

| 字段 | 来源 | 规则 |
|---|---|---|
| `硬伤数` | 资格门槛不满足 + 必废风险 | `count(①不满足) + count(②必废)` |
| `资格门槛不满足` | ① 中 `verdict=不满足` 且 `type=资格` | 有值才显示 |
| `必废风险` | ② 中 `档=必废` | — |
| `需确认` | ② 中 `档=需确认` | — |
| `投标截止` | 时间轴 `kind=deadline` 的那一格 | 格式 `YYYY-MM-DD HH:mm`；**距今天数只在真实运行时算**，样本文件日期已过，不显示 |

不给「建议投 / 不建议投」的总判定——那是替用户做决策，系统只报事实。

## 三、六块的字段定义

### ① 能不能投（资格门槛）

| 字段 | 类型 | 说明 |
|---|---|---|
| `门槛` | string | 条件本身，**不总结，取原文的规范句** |
| `page` | int | 出处页 |
| `verdict` | enum | `满足` / `不满足` / `待确认` |
| `依据` | string | `company.yaml` 里对应的那个字段值，或判定理由 |

分界规则：**要对照「你是谁」的进这块**（资质、人员、身份、股东关系）；**要对照「你做没做」的进 ②**（交没交、在不在期限内）。

### ② 会不会废（无效情形）

| 字段 | 类型 | 说明 |
|---|---|---|
| `档` | enum | `必废` / `需确认` / `非投标人` |
| `情形` | string | **条件句**，见下方硬规则 1 |
| `后果` | enum | `投标无效` / `资格审查不合格` / `不得参加` / `不予开标` |
| `page` + `role` | int + enum | `p23 无效句`，role 见硬规则 2 |
| `原文` | string | 整条原文，默认折叠，点击展开 |
| `依据句` | string | 原文里那句判档的话（`其投标无效` / `不得参加`） |

**分档依据是原文措辞，不是模型判断：**

| 原文写法 | 档 |
|---|---|
| 投标无效 / 否决 / 不予受理 / 资格审查不合格 | **必废** |
| 不得参加 / 取消资格 / 拒绝 | **必废** |
| 「否则投标无效」但前面带条件（如「如…」「视产品」） | **需确认** |
| 只写「应 / 须」但没写后果 | **需确认** |
| 主体不是投标人（如「投标人不足 3 家，不予开标」） | **非投标人** |

### ③ 交什么（材料）

| 字段 | 类型 | 说明 |
|---|---|---|
| `名称` | string | 文件/证明的名字 |
| `类型` | enum | `附证明` / `代查` / `需填表` |
| `状态` | enum | `有` / `缺` / `待确认` / `代理机构查` |
| `page` | int | — |
| `备注` | string | 已在 ② 判过的写「见 ②第 N 条」，不重复判定 |

- **不再用 `满足/不满足`**——那是判定词，用 `有/缺`。
- 「需填表」的几项（投标函、开标一览表、分项报价表、偏离表）**不占清单主体**，合成一行「格式章 p70–92，点进去看模板」。
- 格式章的空表**不单独出「空位对照」**，归到这里。

### ④ 得多少分（评分）

| 字段 | 类型 | 说明 |
|---|---|---|
| `分类` | string | 价格 / 商务 / 技术（来自表头，可能两级） |
| `评分项` | string | 评审因素原文 |
| `分值` | number | **分项**分值，不填合计 |
| `性质` | enum | `客观` / `主观` |
| `标准` | string | 原文评分标准 |
| `page` + `role` | int + enum | `p34 公式` |

规则：

- 有合计列时，`合计` 单独存表级字段，**不进任何单项**
- 价格公式贴在「投标报价」那一行的 `标准` 里，`role=公式`
- **主观分标「不预估」**，不填任何分数
- 8 项以上的分类，真实网页要**展开全部行**；演示稿可合并

**客观性判据（规则，不用模型）：**

```
客观 ← 含「每个 X 分」「满分 X 分」「有一个得 X 分」「X 个以上（含）」
主观 ← 含「合理 / 完整 / 完善 / 科学 / 针对性 / 可行 / 详细」
```

### ⑤ 什么时候（时间）

时间轴只放**时点**，时长单独一行。

| 类型 | 例子 | 放哪 |
|---|---|---|
| 时点 `kind=deadline` | 获取截止、投标截止、开标 | 时间轴 |
| 时长 `kind=duration` | 有效期 90 日历天、解密 30 分钟 | 轴下横排 |
| 规则性期限 | 质疑 7 工作日、询问答复 3 工作日 | 轴下横排，标「期限」 |

- **保证金金额不进时间**（进 ③）
- **有效期若同时构成废标**，判定写在 ②，这里只留时长与页码
- 时间轴按时间排序，同一时点多件事合并成一个点（截止 = 开标）

### ⑥ 中标后（合同）

固定 5 项：`付款` / `履约保证金` / `服务期或工期` / `违约` / `验收`。

| 状态 | 含义 |
|---|---|
| 有值 | 抽到且带原文抓手 |
| **原文未写明** | 原文确实没写 |
| **待人工** | 我们没抽到（**不许写成「未写明」**） |

- 履约保证金留在这里，**不进 ②**
- 抽不到金额就空着，不拿投标函模板或保证金凭证凑一段解释

## 四、五条硬规则（代码要能校验）

### 规则 1：情形必须是条件句，且含情态/否定词

**这是最容易出错的一列。** 实测踩过：

```
原文：投标人不能提供任何有选择性或可调整的报价……否则其投标无效。
错误写法：提供选择性或可调整的报价        ← 丢了「不能」，语义反转
正确写法：若提供有选择性或可调整的报价
```

校验：

```python
MODAL = re.compile(r"不得|不能|禁止|严禁|应|须|必须|不予|未|不低于|不超过")
if not MODAL.search(情形):
    情形 = 原文整句          # 回退，不猜
    flag = "照抄原文"
```

**禁止用名词短语**写这一列。

### 规则 2：页码必须带角色

| role | 用于 |
|---|---|
| `金额` | 保证金、预算、限价 |
| `无效句` | 「投标无效 / 否决」所在句 |
| `资格句` | 「不得参加 / 取消资格」所在句 |
| `期限` | 时长、工作日 |
| `公式` | 价格分计算式 |
| `格式` | 空表、模板 |
| `程序句` | 主体不是投标人（不予开标等） |

不定枚举，就会出现「p8 金额、p17 无效句」和「p8、p17」两种写法并存。

### 规则 3：无原文抓手的行删掉

「实质性响应招标文件」这种没有独立原文句的行不进表。实测删了 2 条（与 p15「否则投标无效」重复）。

### 规则 4：同一件事只判一次

材料行如果已在 ② 判过（保证金没交、总监专业不符），材料行只写「见 ②第 N 条」，不写第二遍「不满足」。

### 规则 5：三态，不许合并

`有值` / `原文未写明` / `待人工`。
把「抽取失败」写成「未写明」，等于把系统的错伪装成文件的错——这是最危险的一类误导。

## 六、两条已知的取舍

**1. 不做总判定。** 不输出「建议投 / 不建议投」——系统只报事实（哪条不满足、哪条必废、什么时候截止），决策留给投标人。理由：判定的依据是 `company.yaml`，而那份文件的完整性和真实性系统无法保证。

**2. ★/▲ 只在条款正文前出现才单列。** 审查项名字里的「★号条款响应」不算（那是表格单元格里的文字，不是条款标记）。北京这份没有条款正文前的 ★，所以 ② 里一条都没有——这是对的，不是漏抽。
